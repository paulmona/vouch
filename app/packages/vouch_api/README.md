# vouch_api
The mobile app talks to the Vouch server over HTTPS (behind a reverse
proxy, VPN or tunnel of the installer's choosing). Agents never call this
API; they, or a credential broker acting for them, talk to the server over
a local socket that is not part of this contract.

**Flow.** The broker asks the server for an approval. The server sends a
Firebase data message carrying only `kind` and an ID (see `PushData`). The
app fetches the request, shows it, asks for the fingerprint,
and posts a signed decision. The first valid decision wins; other devices
get a `clear` push and a 409 if they answer late.

**Two keys per device.** A key that needs a fingerprint for every use
can only sign while the fingerprint prompt is on screen, and the app
must make calls with nobody looking (heartbeat check-ins, push token
rotation, fetching a request when its push arrives). So each device
holds two P-256 keys, both created at pairing:

- The **decision key** (`public_key` at pairing) signs only
  `POST /v1/requests/{request_id}/decision`. When the server policy
  `require_user_auth` is true it needs user authentication for every
  use, so no decision is ever signed without a fingerprint, face or PIN.
- The **transport key** (`transport_public_key` at pairing) needs no
  user authentication and signs every other operation, including
  `POST /v1/devices/pair` itself.

**Signing.** Every operation is signed, by the transport key except
for the decision, which the decision key signs. The device signs this
canonical string, the
five parts joined by a single `\\n` (LF), no trailing newline:

```
METHOD          upper case, e.g. POST
TARGET          path plus query string exactly as sent, e.g. /v1/requests/pending?limit=20
BODY_SHA256     lower-case hex SHA-256 of the exact body bytes sent (of \"\" when there is no body)
TIMESTAMP       Unix seconds, decimal string, same value as X-Vouch-Timestamp
NONCE           same value as X-Vouch-Nonce
```

Signature: ECDSA P-256 over SHA-256 of the canonical string, DER
encoded, base64url without padding, in `X-Vouch-Signature`. Public keys
are SubjectPublicKeyInfo DER, base64url without padding.

The server rejects a request when: the timestamp is more than 60 seconds
from server time (`clock_skew`, with `server_time` in the error), the
nonce was already used by that device in the last 7 days
(`replayed_nonce`), the device is unknown or unpaired (`unknown_device`),
or the signature does not verify (`bad_signature`).

Test vectors: `api/test-vectors.json` (a throwaway test key).

**Keys.** Android: both keys in Keystore (StrongBox where available),
created with the attestation challenge set to SHA-256 of the setup
token's UTF-8 bytes (the raw 32-byte digest). The decision key requires
user authentication for every use (timeout 0) when `require_user_auth`
is true. iOS: both keys in the Secure Enclave, the decision key with
`.biometryCurrentSet`; iOS cannot attest this, so the server records the
device as `client_asserted`.

**Decision key proof.** At pairing the decision key also signs the
UTF-8 string `vouch-pair-v1\\n` followed by the setup token (ECDSA P-256
over SHA-256, DER, base64url), sent as `decision_key_proof`. This proves
the device holds the decision key on both platforms, and on Android it
is the one fingerprint prompt during pairing.
